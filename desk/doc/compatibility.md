# Compatibility Notes

Intentional differences between `%tla-lus` and the pinned Java TLA+
toolchain (SANY / PlusCal / TLC). Each entry states the difference and why
it exists. Differential tests use normalized oracle output; anything listed
here is a deliberate, documented divergence rather than a latent bug.

The desk contains **no** GUI, Toolbox, `tla2tex`, or Java code or
dependencies; the Java `tla2tools.jar` is used only to build the differential
goldens and is never shipped or called at runtime. The only vendored upstream
text is the MIT `StandardModules` (`lib/tla/stdmods.hoon`, with its provenance
header). Everything the scaffold gate audits — pin, golden reproducibility,
no-GUI/no-Java, MIT provenance, kelvin, `%0→%1` migration, bounded fixture
sizes, the desk manifest, and a well-formed parity ledger — is checked by
`tools/scaffold-gate.sh`. The scaffold gate proves hygiene, **not** Java
parity: the parity ledger (`parity-manifest.md`) still carries `partial` /
`absent` / `oracle-only` rows, and the real release gate (unit 12) is the one
that requires the ledger closed to terminal statuses.

## Unit 4 — Syntactic analyzer

- **Error-message text for rejected parses is not reproduced.** REJECT/ACCEPT
  verdicts match SANY exactly (all 261 corpus cases), and accepted trees match
  node-for-node, but the human-readable text of syntax-error messages is not
  yet byte-compatible. Diagnostic *codes* and source spans are preserved.

## Unit 5 — Module resolution

- Clay stores each module under its **lowercased** name, because Clay path
  segments cannot carry case. The case-sensitive declared-name check still
  runs in `resolve`, so a file/module-name mismatch is still detected.

## Unit 6 — Semantic graph construction

The differential oracle is a normalized semantic tree (`tools/oracle/SemDump.java`),
not raw `XMLExporter` XML. Two fields present in the XML are intentionally
omitted from the normalized form:

- **Volatile UIDs** — SANY assigns global sequential node IDs that depend on
  load order and the built-in operator table; they carry no semantic content
  and are excluded.
## Unit 7 — Level checking

Levels (0 constant / 1 state / 2 action / 3 temporal) are now computed and
emitted (`L<level>` on every node) and match SANY across the corpus,
including the cross-definition `spec` case. Two behaviors to note:

- **Unreferenced formal parameters keep level `-1`.** SANY never level-checks
  a formal parameter that the body does not use, so its level stays at the
  uninitialized sentinel `-1` (e.g. `b` in `Foo(a, b) == a`). This is
  reproduced exactly rather than normalized to 0.

Deferred to a later increment (tracked here):

- The full **level-constraint machinery** — level parameters,
  `SetOfLevelConstraints` / `SetOfArgLevelConstraints` for higher-order
  operator arguments, and iterative recursive level checks — is not yet
  ported. The direct level *value* is computed; the constraint checks that
  reject certain higher-order or cross-substitution misuses are not.
- **Level-error diagnostics** (prime inside prime, temporal nesting,
  wrong-level `.cfg` targets) are not emitted. As in unit 6, SANY recovers
  from these with partial trees rather than failing, so they need the
  semantic diagnostic channel.
- **`Linter.java`** (record-constructor field-name clash, with its
  suppression/elevation settings) is not yet ported.

## Unit 9 — Constant evaluation

Constant TLA+ expressions evaluate to canonical values matching the TLC REPL
(`tlc2.REPL`) across the corpus. One deliberate divergence:

- **String ordering.** TLC orders `StringValue`s by their internal
  `UniqueString` id — the order strings were first interned during the run —
  which is not lexicographic and not reproducible without replicating the
  interning table. Strings (and record fields, and string-set elements) are
  ordered **lexicographically** here. This agrees with the oracle on ordinary
  string sets (e.g. `{"a", "b"}`) but can differ on adversarial cases such as
  `{"bb", "a", "ab"}`.

Not yet ported (later unit-9 increments): `.cfg` config parsing (keywords,
constant/model-value assignments, `SPECIFICATION`/`INIT`/`NEXT`, invariants,
properties, constraints, symmetry), model values, the StandardModule Hoon
override contract beyond the operators exercised, fingerprints, and full
lazy/enumerable value semantics for large sets.

Deferred to a later unit-6 increment (tracked here, targeted well-formed
modules only for now):

- **Semantic error recovery.** For ill-formed input (undefined operator
  reference, duplicate top-level symbol, arity mismatch) SANY does *not* fail:
  it builds a partial `ModuleNode` with `nullODN` sentinel operators, keeps the
  first of a duplicated definition, and records the problem on a separate
  diagnostic channel. The current port targets well-formed modules and does not
  yet reproduce these partial trees or emit the semantic diagnostics.
- **EXCEPT** (`$Except` / `$Seq` index nesting), **INSTANCE / substitution**
  semantics (`$SubstIn`, `APSubstIn`), **N_SetOfRcds**, proof/theorem/assume
  expression bodies, and subexpression `!`-navigation are not yet translated
  into the semantic graph (they parse correctly at unit 4).

## Unit 10 — Safety model checking

Deterministic single-worker BFS matches `tlc2.TLC` on the curated cases
(`gen-mc-tests`, 5 cases incl. liveness). Not yet ported (tracked; each is an
`absent`/`partial` row in `parity-manifest.md`):

- **Real FP64 fingerprints.** State identity uses the canonical
  sorted `var = render(value)` string, not the `FP64` 64-bit fingerprint.
  Agrees on the curated specs; the raw *generated* count can differ from TLC
  for specs whose enumeration order TLC computes differently.
- **State/action constraints, `SPECIFICATION` form** (Init `/\` `[][Next]_v`),
  **multiple invariants/properties, symmetry reduction, coverage counters,
  assumptions, and implied-init/action** checks are absent.
- **Checkpoint slices** — the queue/visited-set/predecessor data are not yet
  persisted in bounded slices (one capped `run-check` per event; see unit 13).

## Unit 11 — Liveness / temporal checking

Liveness is checked only under the **no-fairness** semantics (TLC permits
infinite stuttering at any reachable state), which makes `<>P` / `[]<>P` / `[]P`
decidable by reachability with a stutter self-loop lasso. This is a real
divergence from a fairness-constrained run and is **only correct for specs
without a `SPECIFICATION`/fairness constraint**. Not ported (`partial` row
`tlc-liveness`):

- **Fairness** (`WF_`, `SF_`, `wf-next`), the **tableau / SCC / Büchi**
  machinery for real non-stuttering lassos, **`P ~> Q` leads-to**,
  `SPECIFICATION`-form fairness, and the **liveness + symmetry**
  unsupported-combination diagnostics.

## Unit 12 — Simulation, checkpointing, recovery

Seeded simulation is tested as **engine properties** (reproducibility, bounded
termination, violation discovery), *not* as a byte-for-byte oracle:

- **RNG divergence (approved).** Random successor choice uses the Hoon `og`
  core, not TLC's `RandomGenerator`; exact seeded-trace parity with
  `tlc2.TLC -simulate` would require porting TLC's RNG state, seeding/aril
  behavior, and enumeration order. Row `tlc-util-rng` = `approved-difference`.
- Absent: symmetry, checkpoint/resume across Gall restart, cancellation inside
  enumeration loops, structured partial statistics on resource limits, DFID,
  and the benchmark suite.

## Unit P2-1 — Resumable job kernel (supersedes the unit-13 stub engine)

The job engine (`lib/tla/job`) is now a budgeted continuation kernel: one
Gall event spends at most `default-budget` work units (states registered or
generated, transitions, or modules parsed) and persists a versioned, jammed
continuation (`$kont %1`) inside the `%2` job noun. Pause/resume at **every**
slice boundary is tested to produce an identical event stream and final job.
Consequences:

- **No stub stages exist.** The former placeholder `%parse`, `%semantic`,
  `%level`, `%lint`, `%translate`, `%explore`, `%simulate`, and `%terminal`
  stub bodies are gone. Every operation either runs the real pipeline or is
  rejected by type at submit (`+validate`) naming the unsupported behavior
  and its plan unit. A request can no longer finish `%ok` without the named
  work having run.
- **Per-event slicing.** The safety search, liveness graph build, liveness
  property scan, and seeded simulation all run behind persisted cursors
  (`bfs-cursor`, `sim-cursor` in `lib/tla/check`). The simulation cursor
  saves the raw RNG sample, so slicing cannot change the random choices.
  Two enumeration atoms remain un-sliceable until B5's enumeration cursors:
  solving the Init predicate (one `+gen` call at `%config`) and generating
  one state's successors (one `+gen` call per queue entry).
- **Limits at the point of growth.** `max-states` and `max-depth` are
  checked as each state registers inside the search; `max-time` is checked
  against the submit time on entry to every slice; `max-artifact` before
  storing the report; `max-source`/`max-modules` at validate. All six
  request limits are now enforced (`max-time` previously was not).
- **State `%2` migration.** Terminal `%1` jobs carry over verbatim; active
  `%1` jobs ran the stub pipeline and cannot resume honestly, so they
  terminate `%failed 'restarted: the stub pipeline was superseded;
  resubmit'`.
- **Real artifacts.** A finished check stores a TLC-style `%report` text and,
  on violation, a typed `%trace` artifact (`%safety`, `%lasso` with
  `loop-start`, or `%simulate`). The stub translation/cfg artifacts are gone.
- **Simulation mode is live.** `%check` with `mode=%simulate` runs the real
  property-tested seeded engine (unit 12) through the kernel. Its `run-stats`
  map differently: `generated` = transitions taken, `depth` = deepest
  transition index; `distinct`/`queued` stay 0.

Still absent after P2-1 (tracked in `parity-manifest.md`): Clay sources
(typed-rejected at submit), PlusCal translation and translate-before-check
(typed-rejected), `%analyze` semantic/level/lint flags (typed-rejected),
multi-module resolution inside `%check`, canonicalized search roots,
content-hash caching, quotas, artifact retention.

## Typed-rejected / unsupported public options — summary

`parity-manifest.md` §"Public request options" is the authoritative,
machine-checked list. Options a caller can set today that do **not** produce
a run (all rejected at submit with the message shown, never silently
ignored):

| Option | Rejection |
|---|---|
| `op` = `%translate` | `unsupported: PlusCal translation is not ported yet (unit 8)` |
| `op` = `%analyze` with `semantic`/`level`/`lint` | `unsupported: %analyze <flag> stage is not wired yet (unit 3/4)` |
| `check-opts.translate` = `&` | `unsupported: translate-before-check is not ported yet (unit 8)` |
| `check-opts.cfg` = `` `name `` | `unsupported: cfg source override; put the config in the bundle` |
| `%check` without a bundle cfg | `a %check request requires a config` |
| `src` = `%clay …` | `unsupported: %clay sources are not loaded yet (unit 10)` |
