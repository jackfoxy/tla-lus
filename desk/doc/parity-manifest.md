# Parity Manifest

Machine-checked parity ledger for `%tla-lus` (PORT-COMPLETION-PLAN-2 unit 0).
One row per included Java behavioral cluster (granularity matches the
`port-map.md` §4 inventory) and one row per public request option. Every row
carries a `status`; `tools/check-parity.py --check` fails if any status is
blank or not one of the closed set below, so nothing in scope stays
unclassified.

Status values:

- `parity` — Hoon behavior differentially matches the pinned Java oracle.
- `partial` — a first increment matches a narrow slice; named behavior is
  still missing (see rationale).
- `approved-difference` — a deliberate, documented divergence (see
  `compatibility.md`), tested as such.
- `replaced` — the Java mechanism is intentionally supplanted by a Hoon/Gall
  mechanism; no byte parity is meaningful.
- `absent` — in scope, not yet implemented.
- `excluded` — out of scope per the plan; rationale states why.
- `oracle-only` — goldens are captured from the pin but no Hoon comparator
  exists yet.

This ledger **closed at the end of R1** — all 125 rows `parity`,
`approved-difference`, `replaced` or `excluded` — and R1's acceptance was
asserted and recorded against that state (`tools/r1-acceptance.py`, 4/4 clauses,
release gate PASS, ship suite `ok=%.y`).

> **R2.0 deliberately re-opened it.** R2 widens scope: capability R1 excluded
> (Clay write-back, DFID, `TLCGet`/`TLCSet`, `Randomization`, non-debugger
> `TLCExt`), four config capabilities that were typed rejections (VIEW, ALIAS,
> cfg source override, INVARIANT+PROPERTY together), the driver surface
> re-decided as capability rather than CLI, and six approved differences R2 no
> longer approves. Two rows are **new**: `cfg-view` and `cfg-alias`, which had
> never had rows of their own.
>
> **So `tools/release-gate.sh` gate R1 FAILS and `tools/r1-acceptance.py` prints
> `R1 NOT ACCEPTED` for the whole of R2. That is the intended state, not a
> regression.** Read a red gate mid-R2 as "R2 in progress". R2.9 closes the
> ledger again against `tools/r2-acceptance.py`.
>
> `r1-acceptance.py` must **not** be edited to pass. It stays as the record of
> what R1 actually proved.

Counts are cited from the generated `evidence-counts.md`, never hand-written.
