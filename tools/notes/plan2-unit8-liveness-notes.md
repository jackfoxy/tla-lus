## LivenessDump projection (the parity target)

Per case, a stable, UID/timing/thread-free projection:

```
LIVENESS
VERDICT <ok|violated-property|error>
EC <primary-error-code>              (0 on success)
WARN <code>                          (feature warnings; 2279 = symmetry+liveness)
PROP <name>                          (one line per violated property; violation only)
STAT generated|distinct|queue|depth <n>
CLASS <stuttering|back-to-state>     (violation only)
LOOP <n>                             (violation only; loop-target state number)
TRACE <count>
STATE <num> <fp-unsigned-hex|-1>
LABEL <action label / <Initial predicate> / Stuttering / Back to state>
<state variable bindings, verbatim TLC rendering>
ENDSTATE
```

Source of each field (recorded EC code → args):

- verdict/EC: priority scan — 2116 `TLC_TEMPORAL_PROPERTY_VIOLATED` →
  `violated-property`; 2193 `TLC_SUCCESS` → `ok`; everything else
  (assumption 2104/2105, invariant 2107/2110, deadlock 2114, or a lower 21xx)
  is projected as `error` because those are not temporal verdicts — a liveness
  fixture that trips one is mis-authored (see `box-state` below for the one
  deliberate exception, where TLC's own routing produces 2110).
- `PROP`: `TLC_TEMPORAL_PROPERTY_VIOLATED` (2116) records the violated property
  name(s) as a single `String[]` (from `Liveness.findViolatedProperties`), in
  that method's iteration order.
- `WARN`: `TLC_FEATURE_UNSUPPORTED_LIVENESS_SYMMETRY` (2279). See the approved
  difference below.
- stats: `TLC_STATS` (2199) `[generated, distinct, queue]`, `TLC_SEARCH_DEPTH`
  (2194) — same records SafetyDump reads.
- trace: `TLC_STATE_PRINT2` (2217) records the `TLCStateInfo` + ordinal, exactly
  as safety; action label = `info`, bindings = `state.toString()`, fingerprint
  = `state.fingerPrint()` unsigned-hex. The lasso is closed by one of two
  markers, and this is where liveness differs from safety:
  - `TLC_STATE_PRINT3` (stuttering): `LiveWorker` printed
    `StatePrinter.printStutteringState(num)`. `CLASS stuttering`; the loop
    target is the last real trace state (`LOOP = states.size()`).
  - `TLC_BACK_TO_STATE` (2122): a genuine cycle. **Recorder-shape gotcha:** we
    run with `ToolIO.setMode(TOOL)` but *not* the `-tool` CLI switch, so
    `TLCGlobals.tool` is FALSE and `printBackToState` takes the `printMessage`
    branch (`StatePrinter.java:130`), recording a plain `String[]{ stateNum,
    actionInfo }` — the loop-target number is **index 0**, not the
    `[stateInfo, num]` shape `printState` would give. `CLASS back-to-state`,
    `LOOP = arg 0`. (SafetyDump's dead back-to-state branch reads index 1 and is
    never exercised; do not copy it.)

## astToLiveAppl opcode → LN* dispatch (the normalization spec for 8.1)

`Liveness.astToLiveAppl` (`Liveness.java:180`) switches on `BuiltInOPs.getOpCode`
of the operator node; a user-op with opcode 0 is expanded (`Tool.eval` if the
body is constant-level, else recursively translated). The temporal cases:

- `OPCODE_land`/`OPCODE_cl` (∧, ConjList) → `LNConj`
- `OPCODE_lor`/`OPCODE_dl` (∨, DisjList) → `LNDisj`
- `OPCODE_lnot` (¬) → `LNNeg`
- `OPCODE_implies` (⇒) → `LNNeg(LNConj(a, ¬b))`-style rewrite
- `OPCODE_be` (∃ bounded) → `LNDisj` over the enumerated domain; `OPCODE_bf`
  (∀ bounded) → `LNConj`
- `OPCODE_box` ([]) → `LNAll`; `OPCODE_diamond` (<>) → `LNEven`
- `OPCODE_prime` (') → `LNNext`
- `OPCODE_wf` / `OPCODE_sf` → the fairness live-expression forms
- `OPCODE_leadto` (~>) → desugared to `[](P ⇒ <>Q)`
- `OPCODE_aa` (⟨A⟩_e AngleAct) / `OPCODE_sa` (□[A]_e) → action forms
- `OPCODE_ite` (IF) → conditional expansion
- else: a state-level or action-level leaf → `LNState` / `LNStateEnabled`
  (ENABLED) / `LNAction`; a constant `IBoolValue` folds to `LNBool.TRUE/FALSE`.

`processLiveness` (`Liveness.java:664`) then normalizes to DNF, splits the
top-level property into `OrderOfSolution` disjuncts, and per disjunct builds the
`PossibleErrorModel` (the `classifyExpr`/`OSExprPem`/`addToBin` machinery at
`Liveness.java:935-1050`): `EAAction` (eventually-always), `AEAction`
(always-eventually / fairness), and state promises. This is the 8.1 target.

## Approved difference — symmetry with liveness (fixture `symmetry-live`)

TLC does **not** reject symmetry combined with a temporal property. In
`AbstractChecker.java:121` it prints the warning
`TLC_FEATURE_UNSUPPORTED_LIVENESS_SYMMETRY` (2279) — *"Declaring symmetry during
liveness checking is dangerous. It might cause TLC to miss violations of the
stated liveness properties. Please check liveness without symmetry defined."* —
and then **continues checking under symmetry**, possibly missing violations. The
`symmetry-live` fixture confirms this: `VERDICT ok`, `WARN 2279`.

The port instead issues a **typed rejection** at config time (`check.hoon`
`search-ctx` and `job.hoon` `do-config`), refusing the combination outright.
This is safer (never silently misses a violation) but is a deliberate
divergence from the pin. 8.7 pins the port's message/EC to 2279's text rather
than the current placeholder `'unsupported: symmetry with a temporal property
(unit 8)'`, and records the difference in `compatibility.md`. The oracle's
`WARN 2279` line exists precisely to hold this evidence.

## Baseline routing fact — `[]P` over a pure state predicate (fixture `box-state`)

`[](x = 0)` is **not** checked as a temporal property by TLC: `processLiveness`
lifts a box of a pure state predicate into an ordinary **invariant** (the safety
path). The oracle therefore reports `VERDICT error / EC 2110`
(`TLC_INVARIANT_VIOLATED_BEHAVIOR`) with a numbered behavior trace, **not** a
lasso. The port's first-increment `+unwrap-prop` treats `%box` as a liveness
kind and stutter-checks it — a divergence from TLC's routing that 8.1/8.9 must
reconcile (a pure-state `[]P` should route to the invariant engine, unit 7). The
`box-state` fixture pins the oracle behavior so the reconciliation has a target.

## The 8.1 structural oracle (the parity target)

`tools/oracle/LivenessStruct.java` drives `FastTool` (SANY + SpecProcessor, so
SPECIFICATION fairness and PROPERTY temporals are resolved) then
`Liveness.processLiveness(tool, true)` and, per `OrderOfSolution`, projects:

```
LIVESTRUCT
OOS <count>
--- <i> ---
PROMISES <n>          getPromises().length (LNEven[], the <>-promises)
CHECKSTATE <n>        getCheckState().length ([]<>S state bin)
CHECKACTION <n>       getCheckAction().length (union of []<>A and <>[]A action bin)
PEMS <n>              getPems().length (disjuncts sharing this tf)
TABLEAU <node-count>  getTableau().size() (built here; the graph is unit 8.2)
TF
<OrderOfSolution.toString()>   the padded rendering of the tableau formula + pems
ENDTF
```

Captured per case as `desk/test-data/liveness/<case>/struct.txt`, byte-stable
across runs (verified: generate twice, diff the tree). `box-state` yields
`OOS 0` (the `[]state`→invariant routing — no temporal solution). `temporal.hoon`
plus its renderer must reproduce this projection.

**Leaf rendering fact:** `OrderOfSolution.toString()` renders `LNState`/
`LNAction`/`LNStateEnabled` leaves as the underlying semantic `ExprNode`, whose
`toString` is its **`Location`** (`line L, col C to line L2, col C2 of module M`)
— *not* the expression text. This is deterministic per fixture (the `.tla` is
fixed) and is exactly the `Location.toString` format already reproduced
elsewhere (WU4 level `2272`). So the Hoon leaves render from `at=sspan`, and the
live-expr structure is span-identified, not text-identified.

## astToLive: semantic node → live-expr (the port spec)

`Liveness.astToLive` (`Liveness.java:49-178`) + `astToLiveAppl`
(`Liveness.java:180+`). The **leaf decision is level-driven**, and WU3/WU4
already stamp `lvl` on every `sem` node — so the Hoon port reads `lvl`, it does
NOT re-derive levels:

- `lvl == 0` (constant): `tool.eval` the expression to a boolean → `LNBool`
  (TRUE/FALSE). The only case needing the evaluator; node-eval supplies it.
- `lvl == 1` (state): `LNStateAST` — a state-predicate leaf.
- `lvl == 2` (action): `LNAction` — an action-predicate leaf.
- `lvl == 3` (temporal): recurse via the op dispatch; a leaf here is a
  `TLC_LIVE_CANNOT_HANDLE_FORMULA` reject.

Op dispatch (`astToLiveAppl`, keyed on the `sem` op name; WU3 builtin names in
`semantic.hoon` `builtin-ops`):

- `\land` / `$ConjList` → `LNConj`; `\lor` / `$DisjList` → `LNDisj`.
- `\lnot` / `\neg` → `LNNeg` (temporal arg) else fall through to a leaf.
- `=>` (implies) → `LNDisj(LNNeg(a), b)` (temporal) else leaf. Material
  implication; TLC has no logical-implication live node.
- `'` (prime) → `LNAction` leaf. `$AngleAct` `<A>_e` → `LNAction(A, sub=e)`.
- `[]` → `LNAll`; `<>` → `LNEven`.
- `$WF` `WF_e(A)` → `LNAll(LNEven(LNDisj(LNNeg(ENABLED<A>_e), <A>_e)))`
  = `[]<>(¬ENABLED<A>_e ∨ <A>_e)`. Args order = [e A] (subscript first).
- `$SF` `SF_e(A)` → `LNDisj(LNEven(LNAll(LNNeg(ENABLED<A>_e))), LNAll(LNEven(<A>_e)))`
  = `<>[]¬ENABLED<A>_e ∨ []<><A>_e`.
- `~>` (and `-+->`) `P ~> Q` → `LNAll(LNDisj(LNNeg(P), LNEven(Q)))`
  = `[](¬P ∨ <>Q)`.
- `$IfThenElse` → conditional expansion; `$BoundedExists`/`$BoundedForall` at
  temporal level → `LNDisj`/`LNConj` over the enumerated domain (needs node-eval
  enumeration; NOT hit by the corpus — the corpus's only `\E` sits *inside* a
  state-pred leaf and is therefore opaque to astToLive).
- `LetIn` → translate the body; `SubstIn` → translate under the substitution;
  `Label` → translate the labelled body.

These expansions are directly visible in the frozen `struct.txt` goldens (e.g.
`wf-pass` TF shows `[]<>(¬ENABLED ∨ <A>)`; `sf-pass` shows the SF split into two
pem disjuncts; `leadsto-*` shows `<>(P ∧ []¬Q)` after negation+DNF).

## parseLiveness + processLiveness (the decomposition spec)

`parseLiveness` (`Liveness.java:576`): build `livespec` = conj of the fairness
`Action`s (`tool.getTemporals()`), and negate the properties
(`tool.getImpliedTemporals()`) — one property → `LNNeg`, many → `LNDisj` of
`LNNeg`s — then conjoin. Counterexample form is `livespec ∧ ¬livecheck`.

`processLiveness` (`Liveness.java:664`): `tagExpr(1)` (leaf tags for equality),
then `simplify().toDNF()` (pushes negation to the atoms). Split the DNF into
disjuncts; per disjunct `classifyExpr` sorts conjuncts into `OSExprPem`:
`<>[]A`→AEAction, `[]<>A`→EAAction, `<>[]S`→AEState, and the rest→`tfs` (the
tableau formula). Lump disjuncts with syntactically-equal `tf` into one
`OrderOfSolution`; per OOS, `tf.makeBinary()` → `TBGraph` (8.2) +
`extractPromises` (the `<>`-promises); the pems become index arrays into the
shared `checkState`/`checkAction` bins.

## Required Hoon interfaces (frozen for 8.2/8.3 to build against)

- `live-expr`: the LN* tree. **Recursive-mold hazard** — this is precisely the
  zuse-408 fuse-loop surface. Use the obelisk `$+ name` recipe: every node a
  named `+$` with a constant-head `$: %tag ... ==` record; hand-roll every
  recursion over it (no `turn`/`roll`/`zing` — the C1.8 `bail: meme` lesson).
  Leaves (`%state`/`%act`/`%enabled`) carry a `sem` node + its `sspan`; `sem`
  is external to the cycle so it rides as an opaque leaf field.
- `oos`: `[tableau=(unit tb-graph) promises=(list live-expr) check-state=(list
  live-expr) check-action=(list live-expr) pems=(list pem)]`; `tableau` is `~`
  until 8.2 fills it.
- `pem`: `[ae-action=(list @ud) ae-state=(list @ud) ea-action=(list @ud)]`
  (indices into the OOS bins, exactly Java's `PossibleErrorModel`).
- `+render-struct`: emits the `LIVESTRUCT` projection above for the differential.

Migration note (8.1 task 5): the `<>P`/`[]<>P`/`[]P` first-increment cases route
through `temporal.hoon` producing the same `live-expr`/`oos` a general property
